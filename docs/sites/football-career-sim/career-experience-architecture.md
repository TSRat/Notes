# 《第 91 分钟》统一职业生涯体验架构

## 核心原则

所有足球内容都必须先回答一个问题：**这会在一名球员的职业生涯里，以什么具体处境发生？**

因此，产品不建立“战术课”“足球产业课”“文化课”等互相分离的知识空间。青训保护、位置训练、数据分析、经纪人、劳动合同、伤病与脑震荡、反兴奋剂、俱乐部所有权、球场无障碍、种族与性别议题、国家队身份和退役教育，全部被建模为同一个球员可能遇到的事件。知识库只在玩家需要理解事件时出现。

## 六个连续阶段

| 阶段 | 典型处境 | 因素组合示例 |
| --- | --- | --- |
| 青训起点 | 进入梯队、学训平衡、第一次选位、保护与举报 | 家庭、成长发育、技术启蒙、场地、性别与无障碍 |
| 职业突破 | 试训、经纪人邀约、首次合同、租借、杯赛登场 | 球探、合同、媒体、阵型职责、体能与恢复 |
| 稳定一线 | 争夺首发、对手分析、定位球、负荷管理、团队关系 | 数据、教练沟通、医疗、球员工会、更衣室文化 |
| 巅峰期 | 欧战与国家队、商业合作、领导责任、所有权变动 | 身份、赞助、治理、赛程、社区、可持续性 |
| 重大转折 | 重伤、脑震荡、禁赛风险、转会冲突、歧视事件 | 医疗伦理、反兴奋剂、法律、心理健康、公共舆论 |
| 传承与退役 | 队长传承、教练教育、青训回馈、第二职业 | 档案与记忆、教育、财务规划、社区与治理参与 |

每个阶段至少包含 8 个可玩或可预览情境；当前数据集总计 56 个情境。阶段是时间位置，不是内容类别。同一个“伤病”主题可以在青训表现为成长负荷，在巅峰表现为赛程风险，在转折期表现为复出与知情同意。

| 原始范围 | 进入球员生涯的方式 |

## 三个同步观察窗口

一个 `CareerExperience` 可同时投射到三个表面：

1. **舆情与消息**：经纪人、媒体、家庭、联盟、社区如何描述或推动事件。
2. **球员与俱乐部**：属性、合同、训练、医疗、所有权和团队关系发生什么变化。
3. **比赛与实践**：事件如何落到阵型职责、训练计划、比赛选择或长期上场机会。

这三个窗口只改变观察角度，不拆分生涯。`ExperienceContext` 负责同步展示它们，`CareerJourneyMap` 负责把事件放回时间线。

## 数据关系

```text
CareerExperience
  ├─ stage: 生涯时间位置
  ├─ surfaces[]: 同一事件出现在哪些观察窗口
  ├─ factors[]: 同时作用的足球因素
  ├─ termIds[] → EncyclopediaTerm: 当下需要的解释
  ├─ sourceIds[] → KnowledgeSource: 高风险内容的官方入口
  └─ stakes: 玩家为什么必须在此刻关心

NewsEvent / MatchEvent / Decision
  └─ experienceId → CareerExperience
```

数据库中的每个术语必须至少被一个生涯情境引用；深链返回该情境。涉及规则、保护、代理、医疗和反兴奋剂的术语附官方来源入口，但不会把外部规范伪装成医疗、法律或合同建议。

## 覆盖契约

- 不新增按学科分割的主路由。
- 新内容必须先进入 `career-experiences.json`，再按需补术语。
- 每个事件至少说明场景、影响因素、风险与三个表面中的一个。
- 敏感或高风险内容必须附来源 ID，并用边界语言提示玩家寻求合格专业人员。
- 自动化测试检查 ID 唯一性、阶段密度、术语可达、来源可达和核心领域信号，防止内容扩展后重新变成孤立百科。
